七、中級提示詞：Gemini Canva 強力提示詞

如果您需要更完整、帶有音訊處理等進階功能的 React 應用程式，請使用以下完整提示詞：

中級完整提示詞 (Prompt) 
使用以下模型 https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-preview-tts?hl=zh-tw
創建react程式，輸入文字便能產出語音，透過呼叫 Gemini 的 TTS (Text-to-Speech) API 來串接語音合成功能，語音要台灣腔，具體實作方法如下：

1.使用專屬的模型端點：
程式碼中定義了 fetchGeminiAudio 函式來處理語音合成。它會向 gemini-2.5-flash-preview-tts 模型發送請求：   
JavaScript
const url = getGeminiApiUrl("gemini-2.5-flash-preview-tts");

2.建構請求 Payload：
在發送 API 請求時，會將要合成的台詞文字放入 contents，並在 generationConfig 中指定回傳格式為音訊 (responseModalities: ["AUDIO"])，同時透過 speechConfig 傳入指定的配音員名稱（voiceName）：   
JavaScript
const payload = {
contents: [{ parts: [{ text: speechText }] }],
generationConfig: {
responseModalities: ["AUDIO"],
speechConfig: {
voiceConfig: { prebuiltVoiceConfig: { voiceName: normalizedVoice } }
}
}
};

3.音訊資料處理與轉換：
Gemini API 會回傳 Base64 編碼的音訊資料。程式碼接收到資料後，會進行一連串的處理：   
- 將 Base64 字串轉換為位元組陣列 (base64ToUint8Array)。   
- 透過 resamplePCM 函式處理音調（Pitch）的變更，重新取樣 PCM 資料。   
- 最後使用 pcmToWav 函式將 PCM 資料加上 WAV 標頭，並轉換成瀏覽器可直接播放的 Blob URL (URL.createObjectURL)。   
JavaScript
const pcmBytes = base64ToUint8Array(inlineData.data);
const processedBytes = resamplePCM(pcmBytes, safePitch);
const objectUrl = pcmToWav(processedBytes, rate);

4.快取與播放：
處理好的音訊資料（包含 PCM 和 WAV URL）會被存入 audioCache.current 快取中，後續播放時（例如 playLine 函式）就直接將該 URL 餵給 HTML5 的 Audio 元素來播放。如果是多句連續播放或匯出，還會進一步將所有音效和語音的 PCM 資料在前端進行混音 (composeMixedFullAudio)。   

5.要在gemini中執行要強調：
環境自動注入 (Auto-Injection)：當在 Canvas 環境中執行這段程式碼時，Canvas 會監聽所有發送出去的 fetch 請求。當它偵測到目標是 generativelanguage.googleapis.com 且 key= 為空時，平台會自動在底層補上當前登入帳號的內部驗證 Token，然後再把請求送到 Google 伺服器。這種設計是為了讓開發者能在沙盒環境中安全地分享、測試程式碼，而不需要把真實的 API Key 寫死在程式碼中。

## 二、Gemini Canvas 生成時的硬性規格

請遵守以下程式限制，避免生成後不能跑：

1. 使用 React、TypeScript、TSX。
2. 使用 `useState`、`useEffect`、`useRef` 管理狀態。
3. 使用 `lucide-react` 圖示，至少包含：Mic、User、Skull、Play、Square、Loader2、Volume2、Edit2、Save、X、Download、DownloadCloud、Sparkles、Wand2、Plus、Trash2、HelpCircle、Clock、AlignLeft、ShieldCheck、AlertTriangle、Clapperboard。
4. 使用 Tailwind CSS className 做介面，不要另外建立 CSS 檔。
5. 單檔完成，不要拆成多個檔案。
6. 預設匯出 `export default function App()`。
7. 不要使用 Node.js 專屬 API，例如 `fs`、`Buffer`、`process.env`，因為 Gemini Canvas 是瀏覽器環境。
8. API 呼叫請使用瀏覽器 `fetch`。
9. 音訊處理請使用瀏覽器可用的 `Uint8Array`、`ArrayBuffer`、`DataView`、`Blob`、`URL.createObjectURL`。
10. 請保留 `const apiKey = "";`，並註明「Canvas 執行環境會自動注入 API Key」。如果是在一般網頁專案部署，則不要把 API Key 寫死在前端，應改由後端代理呼叫。

## 九、Gemini TTS 呼叫方式

請建立 `fetchGeminiAudio(text, voiceName, pitchFactor)` 函式。

它要呼叫：

`https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-preview-tts:generateContent?key=${apiKey}`

請使用 POST、`Content-Type: application/json`。

payload 結構：

```json
{
  "contents": [
    {
      "parts": [
        {
          "text": "要朗讀的文字"
        }
      ]
    }
  ],
  "generationConfig": {
    "responseModalities": ["AUDIO"],
    "speechConfig": {
      "voiceConfig": {
        "prebuiltVoiceConfig": {
          "voiceName": "Zephyr"
        }
      }
    }
  },
  "model": "gemini-2.5-flash-preview-tts"
}
```

回傳後從：

`data.candidates[0].content.parts[0].inlineData`

取得音訊資料。

處理流程：

1. 從 `inlineData.data` 取得 base64 音訊。
2. 將 base64 轉為 `Uint8Array`。
3. 從 `inlineData.mimeType` 解析取樣率，若沒有解析到就使用 24000。
4. 使用 PCM16 重新取樣函式做 pitch 微調。
5. 將 PCM16 包成 WAV header。
6. 用 `Blob` 與 `URL.createObjectURL` 建立瀏覽器可播放與下載的音檔網址。

重試規則：

- API 失敗最多重試 5 次。
- 每次失敗後等待時間加倍，例如 1 秒、2 秒、4 秒。
- 最後失敗要顯示錯誤訊息，不要讓畫面卡死。

## 十、Gemini 文字生成呼叫方式

請建立 `generateScriptWithAI()` 函式。

它要呼叫：

`https://generativelanguage.googleapis.com/v1beta/models/gemini-2.5-flash-preview-09-2025:generateContent?key=${apiKey}`

請使用 POST、`Content-Type: application/json`。

payload 需要包含：

- `contents`：使用者輸入的主題與選擇的風格。
- `systemInstruction`：完整劇本生成規則。
- `generationConfig.responseMimeType` 設為 `application/json`。
- `generationConfig.responseSchema` 定義 title、description、characters、script 的物件結構。

如果模型名稱不可用，請在提示詞中要求生成工具預留一個容易修改的常數，例如：

```ts
const SCRIPT_MODEL = "gemini-2.5-flash-preview-09-2025";
const TTS_MODEL = "gemini-2.5-flash-preview-tts";
```

這樣日後 Google 更新模型名稱時，只需改常數。

## 十一、AI 隨機靈感生成

靈感主題不可寫死在程式明碼中，也不要內建固定主題池。

請建立 `handleShufflePresets()`，每次按下「AI 換一批靈感」時呼叫 Gemini 文字生成模型，即時產生 4 個新的資安或資訊倫理廣播劇主題。

AI 靈感回傳格式：

```json
{
  "presets": [
    {
      "label": "短標題",
      "suggestedStyle": "校園寫實倫理",
      "prompt": "可直接放入劇本生成器的完整主題描述"
    }
  ]
}
```

規則：

- 每次點擊都要加入隨機種子，例如目前時間與 `Math.random()`，讓主題能真正切換。
- `suggestedStyle` 只能從既有風格中選擇。
- `prompt` 要提醒旁白極簡、角色直接對話、學制與時空一致。
- 若 AI 回傳格式錯誤，要顯示錯誤訊息，不要塞回寫死主題。
- 生成靈感時按鈕要顯示載入動畫與「AI 生成中」文字。

## 十二、語音進度動畫

Gemini API 不會回傳精細進度，因此請在前端做「軟進度」：

- 試聽聲音時，按鈕要顯示百分比，例如 `38%`、`72%`。
- 單句語音首次生成時，播放按鈕要顯示百分比。
- 整劇音檔生成時，原本的整體百分比要保留，並在單句 API 等待期間持續緩慢前進。
- 軟進度在請求開始時從 3% 左右起跳，請求未完成時最多爬升到 95%，完成時跳到 100%。
- 完成後短暫顯示 100%，再切換成播放或下載狀態。
- 若發生錯誤，要停止進度動畫並顯示錯誤訊息。

請建立可重用的 `startSoftProgress()`、`finishSoftProgress()`、`clearProgressTimer()` 之類的輔助函式，並在元件卸載時清除所有計時器，避免記憶體洩漏。

## 十三、音訊快取、播放與下載

請使用 `useRef({})` 建立音訊快取。

快取內容：

```ts
{
  url: "WAV Blob URL",
  pcm: Uint8Array,
  rate: 24000
}
```

規則：

- 單句播放時，如果快取存在，直接播放，不重新呼叫 API。
- 若沒有快取，先呼叫 TTS 生成音訊，再播放。
- 修改角色語音、角色音調、單句台詞或 TTS 文字時，要清除對應快取。
- 重新生成劇本時，要清除全部快取與整劇音檔。
- 產生整劇音檔時，依序取得每句 PCM，句與句中間加入 0.45 秒靜音，再合併為一個 WAV。
- 下載單句或整劇時，用 `<a download>` 觸發瀏覽器下載。

## 十四、AI 回傳資料防呆與 ErrorBoundary 避雷

請務必替 AI 回傳的 JSON 加上強固的資料檢查，不要直接相信模型一定會回傳完整欄位。

必要規則：

- `JSON.parse()` 後，先確認解析結果是物件，而且不是陣列。
- `title`、`description` 若不是非空字串，使用安全預設值。
- `characters` 若不是陣列或為空，使用預設角色。
- `script` 若不是陣列或為空，使用預設劇本。
- 每個角色欄位都要逐一檢查：`name`、`description`、`voice`、`avatarColor`、`pitch`。
- 每句台詞欄位都要逐一檢查：`character`、`voice`、`icon`、`color`、`bgColor`、`displayText`、`ttsText`、`pitch`。
- `voice` 必須落在官方語音清單中，不合法時使用 `Zephyr` 或該角色預設語音。
- `icon` 必須是 `Mic`、`User`、`Skull`、`ShieldCheck` 之一，不合法時使用安全預設值。
- `avatarColor` 必須存在於顏色表，不合法時使用 `gray`。

pitch 欄位尤其要防呆：

- 不可直接對 AI 回傳的 `pitch` 呼叫 `toFixed()`。
- 先用 `parseFloat(String(value))` 轉換。
- 再用 `Number.isFinite()` 與 `Number.isNaN()` 檢查。
- 如果不是合法數字，使用 `1.0` 作為安全預設值。
- 畫面顯示音調時，一律使用清洗後的數值再呼叫 `toFixed(2)`。

錯誤訊息也要防呆：

- 不要直接把 Error 物件或任意物件放進 JSX，例如 `{error}`。
- 請建立 `getSafeErrorMessage()`，把 Error、字串、未知物件都轉成安全字串。
- JSX 中顯示錯誤時使用 `{getSafeErrorMessage(error)}`。
- 這可避免原本錯誤觸發 ErrorBoundary 後，又因為 React 嘗試渲染物件而造成「Objects are not valid as a React child」的第二個連鎖錯誤。

## 十五、Google AI Studio 連接與使用方法

### 1. 建立 Gemini API Key

1. 前往 Google AI Studio。
2. 登入 Google 帳號。
3. 開啟 API Keys 頁面。
4. 建立新的 API Key。
5. 如果是第一次使用，Google AI Studio 可能會要求接受服務條款，並可替你建立預設 Google Cloud Project 與 API Key。
6. 複製 API Key。

### 2. 在 Gemini Canvas 使用

如果程式是在 Gemini Canvas 裡執行，通常可以保留：

```ts
const apiKey = "";
```

並讓 Canvas 執行環境注入金鑰。此時不要在畫面上另外做「輸入 API Key」欄位，避免使用者把金鑰暴露在畫面或截圖中。

### 3. 在本機或自己網站使用

如果不是在 Gemini Canvas，而是在一般 React 專案或正式網站部署，請不要把 API Key 寫在前端 TSX 裡。

比較安全的做法：

- 前端只呼叫你自己的後端 API。
- 後端再使用 Gemini API Key 呼叫 Google Gemini API。
- API Key 放在後端環境變數，例如 `GEMINI_API_KEY` 或 `GOOGLE_API_KEY`。
- 不要把 `.env` 上傳到公開 GitHub。
- 在 Google Cloud 中限制 API Key 可用的 API、來源與配額。

### 4. 常見踩雷點

- 不要把 API Key 寫死在公開前端程式碼中。
- 不要把 API Key 貼到公開的提示詞、GitHub、截圖或教學文件中。
- TTS 回傳的是音訊資料，不是一般文字；要讀 `inlineData`。
- 文字生成回傳 JSON 字串時，要先取出 `parts[0].text` 再 `JSON.parse`。
- `responseMimeType: "application/json"` 可以降低 JSON 解析失敗機率。
- `responseSchema` 要明確定義，避免模型少回欄位。
- 每次更新台詞或角色聲音後，要清除舊音訊快取，否則會播放到舊音檔。
- Gemini TTS 的 `voiceName` 必須使用官方支援名稱，拼錯會失敗。
- 前端瀏覽器不能用 Node 的 `Buffer` 處理 base64，請用 `atob`。
- 使用 Blob URL 後，移除或更新音檔時要用 `URL.revokeObjectURL` 釋放資源。

## 十六、可直接貼給 Gemini Canvas 的完整提示詞

請根據以下規格，產出一份完整可執行的 React TSX 單檔程式。最後只輸出 TSX 程式碼，不要輸出說明文。

我要建立一個「資安語音廣播劇工作台」，在 Gemini Canvas 中執行。請使用 React functional component、TypeScript、TSX、Tailwind CSS 與 lucide-react。預設匯出 `App`。請使用 `const apiKey = "";`，註明 Canvas 執行環境會自動注入 API Key。不要使用 Node.js API，不要拆檔，不要建立外部 CSS。

這個工具要能讓使用者輸入資安或資訊倫理主題，選擇劇本風格與長度，呼叫 Gemini 文字生成模型產生廣播劇標題、簡介、角色列表與逐句台詞，再用 Gemini TTS 模型產生每句語音。請支援角色語音調整、角色音調調整、角色試聽、單句播放、整劇播放、單句下載、整劇下載、逐句編輯、新增台詞與刪除台詞。請加入 AI 隨機靈感功能：不要在程式中寫死靈感主題池，每次點擊「AI 換一批靈感」都要呼叫 Gemini 即時生成 4 個新主題，並可點擊套用到主題輸入框。

介面採深色專業控制台風格。上方是 AI 劇本生成區，包含主題輸入框、隨機靈感主題、長度選擇、風格選擇與生成按鈕。中段是角色與配音員管理區，每張角色卡可選 Gemini 語音、選音調並試聽。再往下是劇本標題與簡介，以及準備全劇音檔、下載全劇音檔、播放全劇與停止播放。最下方是逐句台詞卡片列表，每句可播放、編輯、下載與刪除。

預設角色包含旁白、小宇（五年級學生）、神祕的盜帳者、林老師（資訊老師）。預設劇本是「帳號密碼的秘密」：小宇把遊戲密碼設成生日而被盜帳，林老師引導他學會高強度密碼與數位隱私保護。

請提供 30 種 Gemini 官方語音選項：Zephyr、Puck、Charon、Kore、Fenrir、Leda、Orus、Aoede、Callirrhoe、Autonoe、Enceladus、Iapetus、Umbriel、Algieba、Despina、Erinome、Algenib、Rasalgethi、Laomedeia、Achernar、Alnilam、Schedar、Gacrux、Pulcherrima、Achird、Zubenelgenubi、Vindemiatrix、Sadachbia、Sadaltager、Sulafat。旁白建議 Zephyr，年輕男聲建議 Puck，反派建議 Charon，老師或溫和女性建議 Kore。

AI 生成劇本時必須遵守：第一句與最後一句為旁白，中途旁白最多只在重大轉折出現一次；其他內容由角色直接對話。學生角色必須為國小五年級以上、國中或高中，不得是幼兒或國小一至四年級。故事中的學制、年齡、時空、科技背景、角色語音與音調必須前後一致。學生角色音調為 1.08 到 1.12，成人與旁白為 1.0，反派可用 0.70 到 0.90。

AI 文字生成模型請呼叫 Gemini generateContent，設定 `responseMimeType: "application/json"` 與 `responseSchema`，要求只回傳 JSON。JSON 必須包含 `title`、`description`、`characters`、`script`。characters 每個角色包含 `name`、`description`、`voice`、`avatarColor`、`pitch`。script 每句包含 `character`、`voice`、`icon`、`color`、`bgColor`、`displayText`、`ttsText`、`pitch`。生成後程式必須鎖定角色語音與音調，使每句台詞都與角色設定一致。

Gemini TTS 請呼叫 `gemini-2.5-flash-preview-tts:generateContent`，payload 使用 `responseModalities: ["AUDIO"]`，並在 `speechConfig.voiceConfig.prebuiltVoiceConfig.voiceName` 放入語音名稱。回傳後讀取 `candidates[0].content.parts[0].inlineData.data`，將 base64 轉成 Uint8Array，包成 WAV Blob URL。請提供 `base64ToUint8Array`、`pcmToWav`、`resamplePCM` 等函式。音調倍率用 PCM16 線性插值重採樣處理。

請加入音訊快取。單句音訊產生後存在 `audioCache`，重播不重新呼叫 API。修改角色語音、音調或台詞時清除相關快取。整劇播放或下載前，依序產生全部台詞音訊，句與句中間加入約 0.45 秒靜音，合併成完整 WAV。API 失敗最多重試 5 次，每次等待時間加倍，並在畫面顯示錯誤訊息。

請加入語音生成進度動畫。試聽角色聲音、首次生成單句語音、整劇音檔生成時，都要顯示百分比動態進度，避免使用者誤會當機。由於 Gemini API 不提供細分進度，請做前端軟進度：開始時約 3%，等待期間緩慢增加且最多到 95%，完成時跳到 100%，再切換成播放或下載狀態。請清除所有進度計時器，避免記憶體洩漏。

請務必替 AI 回傳 JSON 做完整防呆：如果 `title`、`description`、`characters`、`script` 或任一台詞欄位缺失、型態錯誤、回傳空物件，都要使用安全預設值，不可讓程式因讀取不存在的屬性而崩潰。`pitch` 必須先用 `parseFloat(String(value))` 轉為數字，再用 `Number.isFinite()` 與 `Number.isNaN()` 檢查；顯示音調時只能對清洗後的安全數值呼叫 `toFixed(2)`。錯誤訊息不可直接渲染 Error 物件或任意物件，請用 `getSafeErrorMessage()` 轉成字串，避免出現「Objects are not valid as a React child」的連鎖錯誤。

最後請輸出完整 TSX 程式碼。
